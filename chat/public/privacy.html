How private is interpartes?

What nobody but the participants can see

  • Call audio, video and screen sharing. They are end-to-end encrypted in your browser with a key that is part of the call link, after the #. Browsers never send that part of a link to a server, so the server forwards media it cannot decode.
  • Chat messages. Encrypted the same way (AES-256-GCM, key derived from the link). The server relays ciphertext, never stores it, and forgets a chat room the moment the last person leaves.

What the server does see, and for how long

  • While a call is running: a random room name (there is nothing to type), the nickname of each participant, a random guest account per person, and when each one joined or left. The database lives only in memory. About 30 seconds after a call ends the room and its guest accounts are erased, and a server restart wipes everything.
  • Network: the server necessarily receives connections from your IP address. It keeps no access logs, and the services behind the proxy never see your IP. Error lines that the proxy writes are stripped of IPs and browser details.
  • Chat: an opaque room tag (not the name, not the key), how many people are connected, and the size of messages rounded up to 256 bytes.

Your browser keeps nothing either: the guest login, nickname and call keys exist only in the open tab and are erased when the call ends or the tab closes. Nothing is written to lasting browser storage.

No analytics, crash reporting or third-party services: the browser is told (by the Content-Security-Policy header) to refuse connections to any other server.

Check it yourself

  1. Compare the safety code. Calls and chats show a 12-digit safety code. Read it out to each other. If everyone sees the same digits, you all hold the same key, so nobody was given a different link and nobody else can listen in.
  2. Check the code your browser receives. The full setup is public at github.com/Kinark/interpartes. Run node verify/verify.mjs from it: it downloads every file this site serves and checks it against the official Element Call release hashes and the repository.
  3. Look for the lock. A call without a key in its link would not be end-to-end encrypted. interpartes shows a red warning instead of a safety code if that happens, and strips link options that could turn encryption or reporting on.

Limits

  • Anyone who has the link can join. Share it only with the people you mean to, over a channel you trust.
  • The verification checks the site at the moment you run it. A server that changed its code for one specific visitor could pass the check for everyone else, which is why the safety code matters: it relies only on your own browsers.
  • Your device and browser have to be trustworthy. Encryption cannot protect a call from malware or extensions on a participant's computer.
