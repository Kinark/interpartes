How private is interpartes?

What nobody but the participants can see

  • Call audio, video and screen sharing. They are end-to-end encrypted in your browser with a key that is part of the call link, after the #. Browsers never send that part of a link to a server, so the server forwards media it cannot decode. On top of that, the participants' browsers agree on fresh keys when the call starts and whenever someone joins or leaves. Those keys only exist in memory, so even someone who recorded the encrypted call and finds the link later can't decode it.
  • Chat messages. Encrypted the same way (AES-256-GCM, fresh keys agreed by the participants plus the link's key). The key is removed from the address bar once the chat opens, so it doesn't stay in your browser history. The server relays ciphertext, never stores it, and forgets a chat room the moment the last person leaves.
  • Closing a chat for everyone. In a chat-only room anyone can press "Close for all": everyone is disconnected, the messages disappear from every screen, and the link stops working. To keep it closed, the server remembers the room's opaque tag (not the key) in memory for 24 hours.
  • Amnesia rooms. Only the last 5 messages of each person stay on screen; older ones are deleted. This happens in each participant's browser, so it can't stop someone with a modified browser or a camera from keeping more.
  • Watermark. Every chat is covered in faint small "anonymous chat" text, so any screenshot or recording of it says it was private. A screenshot without it did not come from a real chat here.

What the server does see, and for how long

  • While a call is running: a random room name (there is nothing to type), the nickname of each participant, a random guest account per person, and when each one joined or left. The database lives only in memory. About 30 seconds after a call ends the room and its guest accounts are erased, and a server restart wipes everything.
  • Network: the server necessarily receives connections from your IP address. It keeps no access logs, and the services behind the proxy never see your IP. Error lines that the proxy writes are stripped of IPs and browser details.
  • Chat: an opaque room tag (not the name, not the key), how many people are connected, and the size of messages rounded up to 256 bytes.

Your browser keeps nothing either: your nickname is never remembered, and the guest login and call keys exist only in the open tab and are erased when the call ends or the tab closes. Nothing is written to lasting browser storage.

No analytics, crash reporting or third-party services: the browser is told (by the Content-Security-Policy header) to refuse connections to any other server.

Check it yourself

  1. Compare the safety code. Calls and chats show a 12-digit safety code. Read it out to each other. If everyone sees the same digits, you all hold the same key, so nobody was given a different link and nobody else can listen in.
  2. Check the code your browser receives. The full setup is public at github.com/Kinark/interpartes. Run node verify/verify.mjs from it: it downloads every file this site serves and checks it against the official Element Call release hashes and the repository.
  3. Look for the lock. A call without a key in its link would not be end-to-end encrypted. interpartes shows a red warning instead of a safety code if that happens, and strips link options that could turn encryption or reporting on.

Connection check

When the site opens, your browser quickly checks the connection you are using. It never stops you, but if it finds a problem, everyone in your call or chat sees a warning for as long as you are there (and you see theirs).

  • VPN, Tor, proxy or cloud server. These do not make a call safer here: the call is already encrypted, and they add another company in the middle that can see who talks to whom, when and how much. The check compares your address with public lists of such services. The lists are downloaded from this site and searched inside your browser, so no outside service is asked about you.
  • Two different addresses. If your browser can reveal an address other than the one the site sees, your VPN or proxy leaks, and others in a call may see your real address.
  • Outside code in the page. Browser add-ons or other software that inject code into the page could read the call before it is encrypted.

How your address is checked: your browser makes a one-time key and asks the server which address it sees. The server answers encrypted to that key, so the answer can only be read in your browser. The server of course has to receive your address to answer at all, as every server does; it does not log or keep it. Only the kind of problem (for example "VPN") is sent to the others in your room, encrypted with the room's key, never your address.

Limits

  • Anyone who has the link can join. Share it only with the people you mean to, over a channel you trust.
  • The verification checks the site at the moment you run it. A server that changed its code for one specific visitor could pass the check for everyone else, which is why the safety code matters: it relies only on your own browsers.
  • Your device and browser have to be trustworthy. Encryption cannot protect a call from malware or extensions on a participant's computer.
